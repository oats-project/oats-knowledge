# What was observed

In one week five pieces of one plugin each had a major in every fresh review round, always of one family per piece: a data set's "recorded, never shaped" rule; a panel's tab; a page's states; a guard's own test; a harness loop. Each time the lead stopped the loop at the second or third and asked the author what the spec or the tests did not pin, the answer came in a few lines and was right.

# The classes, and what ended each

1. A CHECK THAT CANNOT FAIL. Written green, never run against the broken code: a check that compared a name where the host renames what it does not hold; a test that took its "recorded original" from the generator under test; a guard's test that made every refusal by the guard's own switch; a new test that removed the very row it was about. Remedy: every test or check a branch adds or rewrites is run once with its fix removed and must fail; the list of those that passed anyway is what the author sends. Checks that read what is NOT there need their own wrong build.
2. ONE RULE, BUT ITS INPUTS KEPT IN SEVERAL PLACES. A single predicate for "failing" was applied by a page, a filter and a sidebar mark that each kept their own copy of the last read, with different lifetimes. Remedy: one kept copy; everything shown is computed from it at the draw; no kept verdict; then a test walks every combination of states rather than the ones thought of.
3. AN EXPECTATION REMOVED WITH THE CODE IT SAT IN. A rework deleted the base's tests with the cards they tested, and facts the screen still owed went with them. Remedy: list every removed expectation with where the fact now is, or the ruling that cut it; anything in neither goes to the lead.
4. THE TEST ITSELF IS THE DANGER (a test of a guard that could start the guarded thing). Remedy: the test runs the dangerous path only where it knows it is in the safe place, and says by name what it did not run elsewhere.

# The rule for the lead

At the second major of one family, do not allow another round: ask the author for the class and its root, rule on that, and brief the next reviewer with the root as the thing to attack. At the cap, decide finding by finding, and consider cutting the behaviour all the majors hang on.
