# A pointer to a list inherits the list's whole extent

Deduplicating instructions moves a rule to one home and leaves pointers to it
behind. A procedure that once held its own copy of a condition set ("before
acceptance: a verdict on each claim, the lead's note, the reader where asked")
now points at the single home, and the single home lists every condition of
the outcome: "what lands a report: all of these", ending with the acceptance.
The pointer kept its old wording: "when every agreement holds, send it for
acceptance". Read together, the step waits for the acceptance it is about to
request.

In the research template's rework to template-v3.0.0 (2026-11-16) the
validator, its tests and a first round of fresh reviewers all passed this; a
second-round reviewer found it by tracing the step through the lead's
composed prompt. The same round found the same shape in a coexistence
recipe: told to merge only two rows of a shared finishing table, a copy beside
the other template kept that template's finishing rule (its PR merged) for a
helper that has no PR.

**How to apply.** After moving a list into one home, find every text that
refers to it as a whole ("every agreement", "all of these", "once ... hold",
"its rows") and make each name the items it waits for, or say which item it
excludes. Brief the reviewer to trace each gate through the composed prompt
of every soul that reads it, beside the deliberate text contracts that
[condensing instructions](condensing-instructions-preserves-load-triggers.md)
already asks to preserve; a merge of shared texts between two ways of working
carries each one's rules whole, never by rows. Composed review across
capabilities is [its own lesson](rule-changes-need-cross-capability-composed-review.md).

Checked at review on 2026-11-16: in the public research template at
template-v2.1.2
([oats-project/oats-research-coordination@52533c2](https://github.com/oats-project/oats-research-coordination/tree/52533c2)),
the landing rules list "what a report needs before it goes for acceptance",
which excludes the acceptance, and the lead's land-on-agreement skill gates its
hand-over step on "when every agreement holds at one revision". That is the
pointer before the move. The template-v3.0.0 rework was not published when
this was reviewed, so the following are source-reported: the moved list ending
with the acceptance, the four review rounds, which round found what, and the
rows-only coexistence merge and its fixes. One rework, not a rate. This lesson
changes no template or skill and claims no automated check: a validator that
reads text structure cannot tell which items a whole-list reference was meant
to wait for, so the remaining guard is the reviewer's trace described above.
