# Decisions

* [A notice about a host fact is said once per command; a notice about a repository stays per repository](notice-frequency-follows-the-facts-subject.md) - A degraded-but-working fallback notice takes its frequency and scope from what the fact is about, deduplicated where it is produced rather than grouped by text at the printers, counted per repository or hidden behind a verbose flag.
* [A declaration-versus-content check runs at sync and reuses the integrity family](declaration-checks-run-at-sync-under-the-integrity-family.md) - A pin whose fetched manifest names another package id is refused by sync, the lock's only writer, under the existing E_PACKAGE_INTEGRITY family with a new why, rather than at spawn, under the manifest-malformed code or a new code; the compatibility claim was proved by enumerating the published tags.
* [Retire warnings preserve event meaning and reader bounds](retire-warnings-preserve-event-meaning-and-reader-bounds.md) - Record retire-hook warnings under their own event kind before later failures can erase them, and enforce a shared text bound in the strict reader's units rather than widening launch semantics or relying on every writer.
* [Retire-hook retry stays inside the completion that was authorized](retire-hook-retry-stays-inside-authorizing-completion.md) - Retry hook-only retirement debt within the bounded deferred completion, not a later automatic actor, and expose unfinished cleanup through doctor rather than cross-home claims.
* [Committed-only settings prevent deployment drift, not committed soul choice](committed-only-prevents-deployment-drift.md) - Refuse host and spawn contributions to committed-only settings in the resolver while allowing soul payloads, because the restriction prevents deployment-local drift rather than privileging workspace files over other reviewed sources.
* [A local schedule's soul check reuses spawn without narrowing legacy acceptance](local-schedule-soul-check-reuses-spawn.md) - Check newly admitted local schedule souls through spawn preview with the run's selectors, retaining the existing local-directory fast path rather than adding a second resolver or new refusals for previously accepted jobs.
* [Delivery stalls use the messaging provider's attention claim](delivery-stalls-use-provider-attention-claims.md) - Delivery failures reach the roster through a provider-owned attention claim because live network reads do not belong on the status hot path and liveness does not establish idleness.
* [Package probes must see the configuration used by the launch](package-probes-must-see-the-launch-configuration.md) - Refuse launch-config args beside a harness package requirement when the native package probe cannot carry them, rather than maintaining a drifting kernel allowlist or a second settings contract.
* [Pre-answer first-run offers through home-scoped native settings](first-run-offers-use-home-scoped-settings.md) - Avoid a blocking renderer offer through an absent-only project setting, accepting the classic-renderer tradeoff instead of sending a key or mutating user-global seen state.
* [Prerequisite refusals distinguish supported baselines from optimizations](prerequisite-refusals-distinguish-baselines-from-optimizations.md) - Enforce the deliberately selected Node baseline with its real error preserved across consumers, while reporting an older Git's working whole-tree fallback instead of refusing it for a performance difference.
* [Waiting claims may withhold an automated keystroke but never authorize one](waiting-claims-may-only-withhold-automated-input.md) - Kernel wake delivery may defer on waiting claims because uncertainty must cost a late wake rather than an unseen approval, without expiring the message or turning a display summary into an input gate.
* [Dialog-claim support is a per-start hook statement, not a manifest promise](dialog-claim-support-is-a-per-start-hook-statement.md) - A real hook run reports this home's claim support after setup, replacing earlier answers even by absence, because module capability and past claims cannot prove what this start installed.
* [Retire's lineage repair falls back on any atomic-write failure](retire-lineage-repair-falls-back-on-any-atomic-write-failure.md) - Retire's lineage repair tries atomic replacement but falls back in place on any failure, preserving the legacy write's outcome rather than adding a new retirement refusal.
* [Launch-value verification is private and best-effort](launch-value-verification-is-private-and-best-effort.md) - A launch-value verifier must resist low-entropy guessing without becoming credential custody, and recording failure must not become a new reason to fail a start.
* [Hot-read imports preserve contracts and static boundaries](hot-read-imports-preserve-contracts-and-static-boundaries.md) - Use a narrow hot-read import table with re-exported leaves and literal specifiers to reduce startup work without changing synchronous consumers, non-hot commands or soul-resolution errors.
* [The CLI compile cache stays in the per-user OATS home](compile-cache-stays-in-the-per-user-oats-home.md) - Keep the CLI's automatic compile cache in the existing per-user OATS home to avoid a shared-directory trust dependency, a second location override and an inherited hook-environment change.
* [The pi bridge prefers the home's kernel shim over ambient discovery](pi-bridge-prefers-the-homes-kernel-shim.md) - The pi bridge explicitly consults the home's launching-kernel shim before ambient discovery, avoiding a new launch variable or public package-root field for a failure confined to an outside-instance wrapper.
* [Stop intent is recorded before termination, but recording is best effort](stop-intent-recording-is-before-termination-and-best-effort.md) - Every intentional kernel stop attempts to record the ended start before termination, but a failed write must not block retirement, accepting a documented double-failure recovery ambiguity.
* [Report-only prompt recognition may use derived labels](report-only-prompt-recognition-may-use-derived-labels.md) - A recogniser that cannot send input may match derived whole option labels together, because a false waiting report has a different consequence from an unwanted keystroke.
* [Resume lookup uses the recorded incarnation and exact home](resume-lookup-uses-recorded-incarnation-and-exact-home.md) - Resume conversation lookup uses recorded creation and start times with exact home cwd, because native receipts survive same-name respawns and a newest-conversation lookup is not a complete-history inventory.
* [Resume selectors and notices are execution-only](resume-selector-and-notice-are-execution-only.md) - Resume selectors and notices belong only to the current execution, because persisting them would make later ordinary starts reopen an old conversation and break pi transcript-root certification.
* [Per-agent scopes are probe-guarded and execution-only](agent-scopes-are-probe-guarded-and-execution-only.md) - Per-agent scope placement uses a real probe in the launch environment and adds no home marker, accepting a residual exit-classification ambiguity rather than changing retirement or process observation.
* [Caller attribution is separate from explicit lineage](caller-attribution-is-separate-from-lineage.md) - Ambient instance context may inform descriptive caller attribution because it gates no authority, while lineage still requires explicit intent.
* [A preview-bound spawn apply may reuse observations](preview-bound-apply-may-reuse-observations.md) - Spawn apply may reuse observations only when a valued preview-decision fence binds the result to what was confirmed, rather than granting observation reuse to writers generally.
* [The pi fresh-home signal comes from runtime sessions filtered to the incarnation](pi-fresh-home-uses-runtime-sessions.md) - The pi bridge uses earlier filed sessions for the current home incarnation to gate its startup resume nudge, avoiding provider-template coupling, home markers and a new kernel-history dependency.
* [Recovery preserves Git state across ref formats, not just paths](recovery-preserves-git-state-across-ref-formats.md) - Retirement recovery preserves a fixed set of Git operation refs and their available objects across ref formats, because path copies and matching status can silently omit them and the comparison must cover what the copier promises.
* [A fixture's tmux directory preserves evidence of unfinished cleanup](fixture-tmux-directory-preserves-cleanup-evidence.md) - A fixture's private tmux directory stays outside its removable base because relocating it inside would let base deletion hide an unended fixture and its surviving server.
* [Shorten SSH fixture paths without moving nested runs beyond the guard](ssh-fixture-paths-preserve-nested-run-visibility.md) - SSH socket pressure is handled in fixture path budgets rather than by lowering the runner's relocation threshold, because a nested run must remain visible to its outer leftover guard.
* [A retire revision binds reviewed facts, not selected exceptions](retire-revision-binds-reviewed-facts.md) - A retire revision covers the facts the caller reviews in every home, with code-derived field coverage and mutation tests replacing exception lists and untested claims of derivation.
* [A consumer filter takes the identity the kernel already reported](consumer-filter-takes-the-reported-identity.md) - A Desktop-facing roster filter accepts the reported workspace key rather than reinterpreting a repository ref, because the consumer holds host identity and a member ref can resolve to a different key.
* [A provider-declared launch variable is the provider's to decide](declared-launch-variable-is-the-providers.md) - A capability-declared launch variable omitted by both the hook payload and explicit launch configuration is removed at the launch boundary, because ambient sources are open-ended and provider-specific or tmux-only fixes cannot close the class.
* [The trust writer refuses metadata it cannot preserve](trust-writer-refuses-unpreserved-metadata.md) - The native trust writer retains verified atomic replacement rather than stripping or speculatively copying file metadata, with a check-specific refusal and the harness's own trust dialog as the supported alternative.
* [A routed preview preserves caller state and includes caller-only consequences](routed-preview-preserves-caller-state.md) - Routed spawn preview requires advertised host support, keeps apply's caller-side refusals, adds consequences only the caller knows, and never turns a preview answer into a saved route.
* [Resource limits do not prove bounded or incremental reconciliation](resource-limits-do-not-prove-incremental-work.md) - Reconciliation acceptance separately qualifies memory, staged-data backing storage, content work and durability work with caps disabled, then proves continued progress with caps enabled.
* [Cache fetch negotiates before one whole-pack retry](cache-fetch-negotiates-before-one-whole-retry.md) - A filtered cache keeps cheap negotiated fetches, then retries once without negotiation on an unknown failure because advertised commits can imply missing delta bases and negotiated non-thin HTTPS fetch was unavailable.
* [Cache fetch cleanup waits out possible writers](cache-fetch-cleanup-waits-out-possible-writers.md) - Failed-fetch temporary files are reclaimed only after the longest fetch can have elapsed because a new write lock and a before-and-after listing cannot establish ownership against older lock-free Git writers.
* [Proven unmatched launch pins refuse fall-through; unchecked pins stay visible](unmatched-launch-pins-refuse-fallthrough.md) - An unmatched host launch pin blocks launches that would fall through, but incomplete discovery cannot prove a mismatch and must remain visibly unchecked.
* [A partial catalog remains an answer in both CLI forms](partial-catalog-remains-an-answer.md) - Exposing catalog problems preserves successful partial-answer semantics across text and JSON, the established diagnostic stream, and the distinction between a problem and a missing item.
* [Retire exclusion belongs to a whole-run claim, not a plan or retry key](retire-exclusion-is-a-whole-run-claim.md) - A whole-run lifecycle claim separates exclusion from freshness and replay; starts preserve contention answers and span restart's stop and relaunch, but cannot borrow stop's claim-write fallback or claim a path without a readable home record.
* [The viewer detach key is caller-chosen and has its own exit status](viewer-detach-key-is-caller-chosen.md) - An opt-in per-viewer key preserves harness input and legacy exit meanings, while a narrow grammar and positive feature detection prevent unsafe silent fallback.
* [Retirement leftovers are reported as facts, not deletion verdicts](retire-leftovers-are-facts-not-deletion-verdicts.md) - Commit reachability cannot establish preservation of uncommitted work, so leftover listings report bounded facts rather than declaring recovery copies or retained worktrees redundant or safe to delete.
* [Home process scans state their visibility limit instead of refusing on every unreadable process](home-process-scan-has-an-explicit-visibility-limit.md) - A home-wide process scan accepts a documented inspection blind spot because rejecting unreadable processes would prevent ordinary lifecycle work, while failure of the scan itself remains unknown.
* [Keep kernel responsibilities generic and capability runtimes complete](kernel-and-capability-responsibility.md) - The kernel resolves, copies and runs the lifecycle through generic seams; capabilities own concrete behaviour, including operating on OATS.
* [Soul declares identity and where its capabilities come from; the workspace versions; the host supplies facts](soul-declares-kind-config-assigns-policy.md) - Location in the soul, versions in the workspace, host and spawn facts in their own homes; packages never carry deployment policy.
* [Integrity, origin and consent are different proofs](trust-approval-and-consent-boundaries.md) - Membership and declaration are trust; the lock proves contained reproducible bytes; host-install consent is separate.
* [Capability resources must outlive package staging](contained-capability-lifetime.md) - An explicit payload boundary and a complete contained copy keep staging and neighbouring paths from becoming runtime authority.
* [Compatibility follows supported adoption, not every intermediate format](evidence-bounded-compatibility-and-migration.md) - Supported adoption bounds compatibility, unrepresentable migrations refuse, and rollout gates and pre-upgrade checks must match the actual outgoing reader rather than assume every new declaration fails the same way.
* [Unknown hook events are forward-tolerant unless required](forward-tolerant-hook-events.md) - Non-required hook events may be skipped to preserve capability composition, but required events still refuse and the tolerance starts only at OATS 0.49.0.
* [Worktree setup is a capability hook, not a repository-file contract](worktree-setup-is-a-capability-hook.md) - A composed capability decides what repository setup runs, avoiding a second kernel trust mechanism based on a file's presence, host opt-in or script scanning.
* [Harnesses start natively; OATS contributes skills and instructions and sandboxes nothing](harness-native-launch.md) - The strict-curriculum target was retired for every harness; bypass flags only on explicit yolo opt-in.
* [Harness authentication is native and user-managed; OATS never handles credentials](harness-native-authentication.md) - OATS launches the harness in its own authenticated context and never parses, copies, stores or wraps credentials.
* [Kernel supplies provider-neutral messaging inputs; the capability owns identity, membership, transport and qualification](messaging-capability-owns-provider-behaviour.md) - Generic payload, identity and team inputs from the kernel; identities, teams, delivery and readiness from the capability.
* [Separate operational home from granted work authority](home-work-authority.md) - Lifecycle identity stays outside disposable work, so work topology never becomes operational or knowledge authority.
* [Live lineage is deliberately bounded](bounded-live-lineage.md) - Sparse explicit relations favour truthful ambiguity refusal over a permanent history or multi-file transaction promise.
* [Preserve recovery authority until the outcome is proven](preserve-authority-until-cleanup-is-proven.md) - Partial failures retain the identity and obligations a retry needs; recovery derives truth from the object.
* [Version baseline digests independently of baseline authority](baseline-digests-have-an-independent-version.md) - Separate digest evolution from the baseline version that gates lifecycle authority, preserving legacy comparisons without rewriting spawn-time evidence.
* [Retire plan notes are bounded summaries, not the full fact record](retire-plan-notes-are-bounded-summaries.md) - Bound retirement summaries without truncating facts or silently extending the plan contract, because readable CLI output must also remain consumable by Desktop.
* [Retire Git reads preserve the spawn baseline's configuration semantics](retire-git-reads-preserve-baseline-semantics.md) - Retire keeps operator global and system Git configuration to remain comparable with the spawn baseline, so its read profile must not be unified with fully isolated observation without an explicit baseline transition.
* [Recovery copies preserve work, not repository-local Git behavior](recovery-copies-do-not-inherit-local-git-config.md) - Nested-repository recovery deliberately omits local Git configuration beyond status semantics, rather than reinstalling agent-selected executable behavior for a later operator.
* [Record locks favor recoverable refusal over live-holder theft](record-lock-liveness-tradeoff.md) - Lock age never overrides a live local holder; the foreign-lock fallback and check-unlink race stay explicit limits.
* [A minimal process boundary avoids permanent private coupling](minimal-process-boundary.md) - A structured public CLI lets independent consumers evolve without freezing private kernel functions.
* [Configured scope is not messaging membership](configured-team-boundary.md) - A declared configuration boundary establishes team scope independently of ambient messaging identity.
