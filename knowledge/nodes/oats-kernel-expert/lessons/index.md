# Lessons

* [spawn --base <branch> starts from the clone's local branch, which may be far behind](spawn-base-branch-starts-from-the-clones-local-ref.md) - oats spawn --repo <clone> --base main names a ref in the clone, so the worktree starts at the clone's local main even when origin is far ahead, unlike a same-repository spawn without --base or worktree add --base; read the preview's from main@<oid> against the remote, omit --base for the soul's own repository, or pass --base origin/<branch>.
* [An unknown hook key makes Claude Code skip the whole settings file, and a headless check hides it](unknown-hook-key-voids-claude-settings.md) - Before 2.1.78 a StopFailure key voids a Claude Code settings file and stops an interactive start at a Settings Error dialog no unattended instance can answer, while a -p run shows nothing, so a new Claude hook key is written only after versioning the executable the launch runs and any failure of that check leaves the key out.
* [A failed turn's claim splits by error class, and Claude's hook matchers are not a partition](failed-turn-claims-split-by-error-class.md) - Only a usage-limit text opens Claude's menu and only rate_limit carries one, while a provider's refusal lands in class unknown, so a failed-turn claim reads attention for classes measured to open no dialog and question for the rest, decided in one hook entry that parses its input because every matcher entry runs for an empty class.
* [tmux's paste guess can bypass a key-table test](tmux-paste-guess-bypasses-key-tables.md) - Burst input can bypass every tmux key table and mask coverage, so disable paste guessing on private key-table test servers rather than changing production paste handling to fix CI.
* [A derived name's absence proves nothing unless it is the producer's name](derived-name-absence-needs-producer-identity.md) - Lost-receipt recovery must establish the producer's actual instance-name derivation before freeing a schedule slot, because a lookup under another spelling can miss a live run.
* [Dialog claims neither enumerate every dialog nor prove one is still open](dialog-claims-do-not-enumerate-all-dialogs.md) - A hook-silent usage-limit menu and a claim surviving refusal show why automated input must treat claim coverage as partial evidence and a long hold as a reason to inspect.
* [A warm process needs lifetime classification, not just a cache-reset list](warm-process-state-needs-lifetime-classification.md) - A warm-reader review missed a process-long WeakMap and misclassified a live-child registry, so repeated kernel calls need explicit reset, drain and safe-with-reason lifetimes backed by closure and equivalence tests.
* [A file argument does not bound the repository test runner](a-file-argument-does-not-bound-the-repository-test-runner.md) - A single-file request through the repository runner unexpectedly selected the full suite, so kernel briefs need an explicit bounded invocation until runner semantics enforce the requested scope.
* [A kernel rewrite does not remove unchanged child waits](kernel-rewrite-does-not-remove-child-waits.md) - Separate process startup and kernel compute from child waits before estimating a language rewrite's benefit, because measured warm-read gains do not remove provider, network or harness costs.
* [Open a CI-only draft during kernel review convergence](draft-pr-runs-ci-during-convergence.md) - When the kernel branch needs a PR to trigger CI, the expert opens a clearly non-review draft on the first push so exact-head CI runs during convergence rather than starting only after acceptance, and states green only from the completed run of the exact head, never from a watch that returned with zero checks.
* [A native start belongs to the launch, not each rendering of its command](native-start-is-prepared-once-per-launch.md) - Preparing native-record state during command rendering can strand an undispatched pending receipt and make history unreadable, so one launch owns one prepared start reused by every render.
* [Pi bridge holds must not wait for their own run](pi-bridge-holds-must-not-wait-for-their-own-run.md) - Detect pi's active-before-start lifecycle by the event's messageType rather than a version gate, because an idle wait inside that run deadlocks and apparent agent work can mask a missing opening task.
* [Real-pi opening races need an executed CI gate](real-pi-opening-races-need-an-executed-ci-gate.md) - The opening-task deadlock escaped a green host-model suite while real-pi tests skipped, so bridge-hold changes need version-qualified real-runtime evidence until CI actually exercises the claimed lifecycle.
* [Spawn probe telemetry can masquerade as Git cost](spawn-probe-cost-is-claude-telemetry-flush.md) - Attribute synchronous child cost before optimizing Git, and keep the Claude telemetry opt-out local to the plugin probe because carrying it into a launch disables channels.
* [A bridge's home marker is retirement state, not harmless bookkeeping](bridge-home-markers-change-retirement.md) - Home bookkeeping needs separate work-retention and copy-permission decisions; avoiding an undeclared bridge marker prevents needless recovery, but classifying a kernel file as a receipt does not keep sensitive bytes out of recovery storage.
* [Contract approval does not carry across a refinement](contract-approval-does-not-carry-across-refinement.md) - The kernel expert must obtain both maintainer sides' agreement to a changed contract shape before building it, because approval of earlier wording and a coordinating expert's agreement do not approve the refinement.
* [Verified recovery does not prove that a home stays removed](verified-recovery-does-not-prove-home-removal.md) - Stop-retire overlap preserved work in the reported probes but could recreate or strand a receipt-only home, so cross-command exclusion must cover removal and late writes as well as preservation.
* [A holderless lifecycle marker cannot support safe recovery](holderless-markers-cannot-support-safe-recovery.md) - Killed start and stop probes left permanent busy markers, while removing a live start's marker admitted two unmanageable harnesses, so recovery needs holder evidence rather than an age or deletion hint.
* [Narrow race evidence needs unpaused controls and bounded fixtures](narrow-race-evidence-needs-unpaused-controls.md) - An exact CLI pause establishes a possible interleaving, not its ordinary reachability, so pair it with unpaused trials and measured window width while bounding fixture resource use; a test of the kernel's answer to a race's outcome needs no gate, only the competitor's effect placed before the act and a step matched by its arguments rather than their position.
* [A tmux viewer's key table is server state, not session state](tmux-viewer-key-tables-are-server-state.md) - Viewer-specific bindings need isolated table ownership and cleanup, while copy-mode and prefix precedence limit what a session key table can promise.
* [A raw-mode terminal child does not protect its wrapper's whole lifetime](terminal-child-signal-gaps.md) - Terminal signal handling must cover setup through cleanup, protect cleanup children from group signals, and allow pending signals to dispatch before the next side effect while preserving the child's outcome.
* [A missing tmux socket does not prove the server exited](missing-tmux-socket-does-not-prove-server-exit.md) - A tmux server can retain sessions after its socket file is removed, so a missing endpoint needs independent liveness evidence before lifecycle code treats work as stopped.
* [Recovery completeness must be measured against the source, not Git's advertised refs](recovery-completeness-needs-source-refs.md) - A successful Git transport copy can omit hidden branches, so recovery must derive its required refs from the source and verify the destination against that independent set.
* [Process identity must survive different readers and host conventions](process-identity-across-readers-and-hosts.md) - Process identity needs stable readers and fail-closed unknown handling; empty arguments can precede exit, while PID existence and a matching start token do not prove an unreaped holder can still act.
* [A refusal that needs the old bytes is a pre-commit gate, never a post-hoc rollback](refusal-belongs-before-commit.md) - Decide inside the transaction while the old state is live; "do it, then undo it" is safe only for a pure inverse.
* [Identity and location belong to the resolved object, never to the string that named it](resolved-object-not-referring-string.md) - Resolved-object checks need independent intended-object authority, including receipt-bound requested homes, native on-disk directory spelling and descriptor identity before reads.
* [Kernel-composed instructions are executable surface and may assert only what every instance has](kernel-composed-text-is-executable-surface.md) - Instructions beat code; shared text states the invariant, and capability content lives in its own inject.
* [Hook failures and error messages are output channels](hook-and-error-channels-disclose.md) - Output safety requires caller-aware redaction or suppression, and a disclosure claim must exercise its real entry point rather than infer reachability from an unsafe renderer.
* [The CLI as a machine boundary](machine-boundary-contract.md) - A machine CLI owes one stdout envelope, honest failure classification and phase-aware refusals, stable typed codes, semantic exit status, deployment-independent explanations and tested remedies.
* [A kernel fail-closed guarantee is proven only by its first real capability user](fail-closed-mechanism-proven-by-first-user.md) - Enforcement, its intended user and the schema must move together.
* [A CLI decision made in two layers, or copied per command, drifts](per-command-enumerations-drift-from-the-dispatch.md) - Keep CLI policy in one authoritative rule, pin unavoidable mirrors, make fallbacks structural, and check a proposed writer's flags against write semantics before approval.
* [An integrity value proves only the exact bytes it covered](an-integrity-value-proves-only-the-bytes-it-covered.md) - Digest raw bytes, never a decoded string; a content-derived id proves content, not authorship.
* [Code that observes another agent's tree must not be able to harm the observer](observation-must-not-harm-the-observer.md) - Observing a tree someone else works in is a security boundary; Git reads must be helper-free (repo-local config and lazy fetch both run executables) and non-writing, signals need verified PIDs, and untrusted entries are never followed or read blocking.
