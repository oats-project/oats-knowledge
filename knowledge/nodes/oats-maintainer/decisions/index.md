# Decisions

* [Protected launch mode is optional and servers-only, one customer per host unless declared, issuance ends at stop with short proofs and no nonce store, and the issuer runs off the agent hosts](protected-launch-mode-is-optional-servers-only-with-an-off-host-issuer.md) - Pepe's side's half of the soul launch authority design, decided 2026-11-10 on his delegation, so a protected launch mode is an option for servers with no laptop profile, hosts hold one customer unless sharing is declared, stop and retire end issuance with proofs of 300 s or less and no nonce store, revoke is the owner's call, and the issuer runs off the agent hosts and fails closed; Juan's side's half is still open.
* [Operators reach agents in a Kubernetes team container through the existing SSH execution target, not a new kubectl-exec target](kubernetes-operator-access-uses-the-ssh-target.md) - For Pepe's side, decided 2026-11-10 with Juan's side's agreement, operators reach agents in a Kubernetes team container through the kernel's existing SSH execution target (sshd in the pod, the operator's ssh configuration using a ProxyCommand over kubectl port-forward), so the kernel stays runtime-neutral with one execution route; a kubectl-exec execution target returns as a contract question for both sides only if a deployment forbids sshd in pods.
* [The tested aw version is published by oats.aweb in its own data file, and onboarding pins aw to it only for a customer-run server](tested-aw-is-published-by-oats-aweb-and-pinned-only-for-byot.md) - oats.aweb publishes the aw versions it was tested with as a public provider-owned data file ({min, tested}) that its floor module reads as the one source and that CI must run exactly; getting-started reads that file only at the catalog-pinned oats.aweb ref and installs aw@tested only on the customer-run (BYOT) branch, while hosted installs keep npm latest and record the installed version, narrowing, for that branch only, the integrations decision's rejection of pinning the install.
* [An uncertain publication refusal carries fixed diagnostic constants, never git's or the remote's text](uncertain-push-refusals-carry-fixed-diagnostics.md) - The knowledge package's uncertain push and delete refusals carry a phase, exit code, allowlisted signal, timeout, elapsed time and an optional cause token from a fixed table matched only on git's own client-side stderr under a C locale; raw and redacted stderr were both rejected, because a gate that withholds output for safety still owes a fixed-vocabulary diagnosis of its own failures.
* [A harvest is published only when the forge reads back an open PR at the exact head; an unlabelled PR is its own status](publication-is-proven-by-the-forge-readback.md) - After the push, knowledge publication is proven by reading the PR back from the forge (open, at the exact screened head, on its own branch, against the accepted base, on the canonical repository, not cross-repository), never by the returned URL's text; only idempotent forge calls are retried, the label is applied after the create, an open PR that could not be labelled gets its own status, and the fix is called fixed only after one live labelled harvest.
* [A retired 4.x seat is harvested from its recovery; a host harvest switch is not an opt-out, the soul's is](a-retired-4x-seat-is-harvested-from-its-recovery.md) - For a retired source only, the knowledge package ignores the removed 4.x harvest keys written by the host, spawn or workspace layer, because they never carried the soul's consent; the opt-out stays the recorded soul.yaml text, which no layer can mask, and a 4.x host harvest-off switch is not a privacy opt-out, since under 5.x the deployment's own act of writing a proposal and spawning a harvester is the consent. Live 4.x homes keep refusing, with the remedy to retire first.
* [No public announcement of OATS until it is polished; a launch is the humans' joint call](no-public-announcement-until-polished.md) - OATS is not announced publicly until its humans together judge it polished enough, so work framed as being for a launch is reviewed on its own merits without launch urgency, and what counts as polished waits on the directing human's list.
* [The host-default harness reuses souls.launch."*", not a second key](host-default-harness-reuses-souls-launch-star.md) - Use the existing host-wide launch preference rather than a second default-harness key, because it must override unavailable soul-declared harnesses and cover souls added later, with per-soul exceptions only for installed and authenticated harnesses.

* [A shared task list selects its team without changing messaging defaults](tasks-team-is-a-workspace-setting.md) - Select the aweb tasks team once in the workspace's tasks payload, not through deployment-local overrides or messaging defaults, so deployments share a task list without moving unrelated identities.
* [Messaging does not compose task coordination](messaging-and-task-coordination-are-separate-choices.md) - Keep task teaching and prerequisites capability-scoped, default onboarding to aweb tasks only without an existing tracker, and keep OATS-installed aweb skills within composition so messaging alone never opts a home into tasks.

* [Operator-default soul selection is not a wording fix](operator-default-soul-selection-is-not-a-wording-fix.md) - Preserve first-by-name operator soul selection when clarifying a confusing notice, because choosing a friendlier soul changes the command's resolved settings and teams rather than just its presentation.
* [Put the reference-theory authoring aid in oats.authoring](knowledge-theory-expert-moves-to-authoring.md) - Move the optional knowledge-theory soul and capability to the existing authoring package rather than expose them in every new framework workspace, with release continuity and existing-home preservation.
* [A workspace front door routes and introduces without mandatory brokering](front-door-routes-and-introduces.md) - For most workspaces, keep an always-alive intake agent that finds or starts the owner and introduces the human, without requiring every later message to pass through it.

* [An own-home checkpoint wake is a routine instance act](own-home-checkpoint-wake-is-an-instance-act.md) - Classify an instance's own checkpoint registration and removal as routine rather than operator work, while retaining the wake-hold prerequisite, its coverage limits, and separate gates for host installation and other-home wakes.
* [OATS moves to its own GitHub org and npm scope by full transfer, in separate stages](oats-moves-to-its-own-org-in-stages.md) - Move OATS and its non-aweb packages to the oats-project GitHub org and npm scope by repository transfer, in stages: the bridge release ships first because it is inert until a declared string changes, the transfer needs no kernel release, the string flip waits for every kernel and schedule unit to be on the bridge, the npm rename comes last under a closed seven-repository contract with a frozen probe name; old names are held by staying empty, never by a placeholder.
* [Human attribution is an optional messaging-capability contract](human-attribution-is-an-optional-messaging-contract.md) - Add human attribution through a provider-neutral messaging contract, default new onboarding to human-bound mode where supported, and preserve unchanged operation for capabilities and deployments without human identities.
* [Host-bound automation is declared in the workspace with explicit execution selectors](host-bound-automation-is-declared-in-the-workspace.md) - Declare shared host-bound automation in the workspace with its required host and account selectors, retaining host-local consent rather than hiding the automation locally or redesigning the binding contract merely to omit those names.
* [The OATS development workspace does not compose oats.cloning](dev-workspace-does-not-compose-cloning.md) - Deliberately leave oats.cloning unpinned and uncomposed in the OATS development workspace while retaining its catalog entry and member repository; restoring consumption needs the deciding human's approval.
* [CLI speed comes from Node fixes and an app-owned warm reader, not a native rewrite](no-cli-rewrite-app-owned-reader.md) - Reject native CLI rewrites in favor of Node fixes and an app-owned warm reader, with a source-reported bilateral contract preserving request freshness, installation checks and CLI fallback.
* [Display observation reuse reports; it never authorizes](observation-reuse-never-authorizes.md) - Reuse a login observation only for display, keep host-execution decisions live, and accept bounded display staleness rather than putting secret-derived values in reuse keys.
* [Refresh maintainer context with a new instance after a coordination-skills release](fresh-maintainers-after-coordination-skills-releases.md) - For the directing human's lanes, use fresh maintainer instances after syncing coordination skills rather than upgrading retained context, defer occupied seats until their efforts land, and replace the release lane last.
* [Background is presentation, not identity or lifecycle](background-is-presentation-not-lifecycle.md) - Background is an instance-owned presentation choice with a soul default, not identity or lifecycle policy; ancestor-based client placement avoids inherited state and a separate presentation record survives restarts.
* [Background defaults belong to short-lived OKF services, not OATS maintainers](background-defaults-are-for-okf-services-not-oats-maintainers.md) - Default the OKF harvester and knowledge-maintainer to background, while keeping OATS maintainers visible as the human's working peers and respecting package-qualified request scope.
* [Parent-child lines require declared shared work, not inferred organisation](parent-child-lines-require-declared-shared-work.md) - Keep parent-child placement while drawing its connector only from a parent-bound shared-work declaration, with coordination guidance owned by capabilities rather than the kernel or oats.core.
* [Lost sessions resume locally through the kernel into their own conversation](lost-sessions-resume-locally-in-their-own-conversation.md) - Lost-session recovery is always on and retriggered by local loss, with a per-boot bound and proven harness selectors, while preserving the instance's conversation, user-owned prompt choices and local-only scope.
* [A client-created tmux server needs its own cgroup](client-created-tmux-server-needs-its-own-cgroup.md) - When a client becomes the usual creator of the OATS tmux server on a systemd host, server placement must keep the agents outside the client's cgroup so a whole-cgroup kill does not take them down together.
* [A client reads reported host facts but may check its own local tool](client-local-tools-and-reported-host-facts.md) - Clients consume kernel-reported host capabilities rather than copying host rules, while a client-owned local tool may be checked locally with mirrored behavior pinned by a cross-owner test.
* [Working and idle are producer-reported facts, not terminal heuristics](instance-activity-is-reported-not-inferred.md) - Harness producers report main-thread activity through one kernel writer, within the existing hook budget, so clients never infer idleness from terminal silence or turn unknown into idle.
* [A human addresses a long-lived agent through threads that are aweb conversations; the soul declares an interaction kind in its messaging settings](humans-address-long-lived-agents-through-threads.md) - Keep the deferred aweb-conversation design and current one-input-surface rule, with a later thread-inbox vision of curated mail and chat for depth as a design criterion after coordination rather than authorization to resume the build.
* [A launch check judges the environment the launch will have](checks-use-the-launch-environment.md) - Launch checks share the launched process's environment model, disclose what they cannot establish, and never pass by silently substituting the spawner's account.
* [Reference display is rebuilt from recognized parts or withheld](reference-display-is-rebuilt-or-withheld.md) - One allow-list renderer serves messages and JSON alike, accepting the diagnostic cost of withholding unrecognized references rather than trying to strip every possible credential span.
* [The capture service belongs to the record package and runs bounded passes](capture-service-is-package-owned-and-bounded.md) - Capture direction replaces the unbounded watcher with package-owned periodic passes, retaining progress and failure isolation while avoiding a second in-pass scheduling mode.

* [Durable specialization preserves judgment across sessions](durable-specialization.md) - Preserve expertise as a versioned project artifact and the soul as canonical curated birth context, while treating agent genomics and speciation as direction rather than replacing shared specialization with per-instance configuration.
* [The OATS soul roster: expert domains own knowledge nodes, developers own none](domain-expert-rebuild.md) - The one canonical roster: domain and package experts own nodes, developer and admin souls own none, release stewardship is a Playbook.
* [Optional reference theory, capability-owned runtime](optional-reference-theory.md) - OATS offers an adoptable reference knowledge theory while each capability owns its runtime and may choose another model.
* [External knowledge needs source-independent custody](external-knowledge-custody.md) - Knowledge custody is separate from source evidence and the work branch; proposals are not accepted knowledge.
* [Centralised per-soul knowledge is the default; capabilities own learning; instances are situated, not short](flexible-knowledge-and-situated-instances.md) - The default routes knowledge centrally per soul, capabilities own their learning model, and speciation follows evidence.
* [Official OATS development runs on the architecture it offers adopters](official-development-dogfoods-the-workspace.md) - The framework and its package repositories form one workspace under one stewardship gate; member and publisher roles never collapse.
* [A workspace definition, a source library and a capability package are different responsibilities](workspace-definition-is-not-a-package.md) - Composition, behaviour, transport and realisation are distinct responsibilities joined only by reciprocal membership; consuming is not joining.
* [Workspace model v2 — membership is trust, location is not version, every capability is copied whole into the instance](workspace-model-v2.md) - Reciprocal membership is the trust decision for members, packages are the only versioned source, and nothing is installed.
* [Operating OATS is capability content; the reviewed list is the marketplace](official-capabilities-and-reviewed-marketplace.md) - Operational knowledge ships as the official core and setup capabilities, and the reviewed catalog defines officialness.
* [Pre-adoption contracts are removed, not translated](clean-contract-precedent.md) - An unadopted shape is removed with a pointed error naming its replacement; published commitments keep reader compatibility.
* [Retired kernel codes need no client list until a removal requires one](retired-kernel-codes-need-no-client-list-until-required.md) - A client may use a truthful generic rendering for retired kernel codes still in its accepted band, deferring a retired-code list until a concrete removal needs it.
* [New kernel lines roll out fresh-install-first; historical migration is deferred, never destructive](fresh-install-first-rollout.md) - Roll out by provisioning fresh deployments; park conversion without erasing or relabelling history.
* [Runtime, messaging and viewers have separate owners; a wake is a hint, not consumption](runtime-messaging-viewer-ownership.md) - The kernel owns execution, the messaging capability owns identity and delivery, and viewers are clients.
* [The served identity is a messaging-layer fact the kernel binds and shows, never kernel vocabulary](served-identity-is-a-messaging-layer-fact.md) - The identity choice travels in the provider payload with no spawn flags; the provider owns every identity rule.
* [Desktop parity: the design's semantics win where safe; where they imply authority OATS lacks, the UI tells the truth](desktop-parity-lifecycle-and-policy.md) - Remove retains work, Stop is recursive, rows render only kernel facts, child spawns are enforced, and the kernel's JSON is the Desktop's model.
* [A forge connection is a workstation fact, not a capability](forge-connection-is-a-workstation-fact.md) - Forge sign-in is a per-machine Desktop connection under the forge CLI's custody; automatic PR is ADE-owned.
* [Team as a first-class config entity](team-as-config-entity.md) - The classic-path team block and what survives of it: the instance name is the messaging alias.
