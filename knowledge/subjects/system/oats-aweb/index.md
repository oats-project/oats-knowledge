## Decision

* [The human alias's host part is read from the deployment's local settings, not the hook environment, by one exported derivation](/nodes/oats-aweb-expert/decisions/human-alias-host-comes-from-the-deployment-not-the-hook-environment.md) - The kernel's hook environment carries no host name, so the provider derives the human alias `<os-user>-<host>` by reading `host.name` from the deployment's `oats-local.yaml` with its own block-style reader, falling back to the short OS hostname, with the real OS user from `os.userInfo()`; one exported function serves the spawn brief and the later mint so a re-mint yields the same alias.
* [settings.oats.aweb.interaction is validated strictly, at spawn and at launch, before any aw call](/nodes/oats-aweb-expert/decisions/interaction-setting-is-validated-strictly.md) - Absent means `terminal`; null, empty, non-string or unknown values are refused with a message naming the key, the received value and both accepted values, following the package's `claudeChannelMode` precedent rather than `delivery`'s silent coercion, because a mis-typed `threads` that silently became `terminal` would give Desktop no panel and the human no explanation.
* [The scheduled publisher reuses the kernel job lock](/nodes/oats-aweb-expert/decisions/publisher-reuses-scheduler-exclusion.md) - A second publisher tick lockfile was rejected because the kernel already serializes runs of the scheduled job and another lock would add a stale-lock failure mode.
* [A readiness cache needs measured publisher cost](/nodes/oats-aweb-expert/decisions/readiness-cache-needs-measured-cost.md) - The health publisher deferred a readiness cache below an agreed approximate one-second per-home threshold, using bounded CLI CPU measurements and a remeasurement trigger rather than treating scratch timings as a production budget.
* [Health receive evidence follows the delivery mode](/nodes/oats-aweb-expert/decisions/receive-evidence-follows-delivery-mode.md) - The health publisher uses matching live and fresh native-stream receipts or fail-closed broker readiness according to delivery mode, because neither a leftover file nor a missing inapplicable receipt proves receive health.

## Insight

### lesson

* [When a home's captured setting blocks the refresh meant to reach it, read live only the fields the refresh changes, and pin the authority fields to the capture](/claims/lessons/a-captured-setting-that-blocks-its-refresh-reads-live-only-the-refreshed-fields.md) - A home captures its provider settings at spawn, so a later setup refresh (a newly mapped team, a new policy) never reaches an existing home's command, and a refusal whose fix is "rerun the refresh" is untrue there; read the live setting for the refreshed fields only, require every authority field (root, human, service, profile path and digest) to equal the captured one, and refuse with "respawn this home" otherwise.
* [A service's member listing finds removal candidates; only a locally held signed copy authorises the removal](/claims/lessons/a-listing-finds-removal-candidates-a-local-signed-copy-authorises-the-removal.md) - A reconcile that removes leaked memberships must never take a certificate id or alias from an unsigned listing as authority; it acts only through the locally held signed copy (looked up by an id of the provider's own form, using the copy's own team and alias), a certificate a live home's record names is that home's whatever the listing says, and a row with no copy is listed, never removed.
* [A rule for one mode belongs in that mode's spawn brief, not in the always-loaded inject, when it is needed at session start](/claims/lessons/a-rule-for-one-mode-belongs-in-that-modes-spawn-brief.md) - When shortening a provider's inject, a rule that applies to one mode only (a grant seat, one delivery path) can live in the brief line the spawn hook writes for that mode, if it is needed at session start; the inject keeps a pointer and any rule the brief lacks. A rule needed later in the session stays always-loaded.
* [A sweep that removes orphaned artefacts reads the artefacts first and their owners after](/claims/lessons/a-sweep-that-removes-orphans-reads-the-artefact-before-its-owners.md) - When owners create an artefact only after they exist and have recorded their claim, a reconcile that removes artefacts no live owner claims must snapshot the artefacts first, then list the owners, then read their records, and only that snapshot is ever a removal candidate; in any other order, an owner created in between makes a live artefact look orphaned.
* [A tested-aw bump rests on aw's own tag-to-tag diff, not on a relayed change list](/claims/lessons/a-tested-aw-bump-rests-on-the-tag-to-tag-diff.md) - Before oats.aweb records a new tested aw, read the aw source paths oats.aweb consumes across every tag from the old tested release to the new one, and write the release note from that; a change list relayed with the request is someone's selection and can miss what reaches oats.aweb.
* [Identity polling should not buy a server request for local facts](/nodes/oats-aweb-expert/lessons/identity-polling-uses-offline-reads.md) - The health publisher chooses offline identity inspection because a per-minute whoami call adds a server request per identity for identifiers already held locally.
* [The suite's real-aw pins age with the installed client — compare against the clean base on the same host before calling a failure a regression](/nodes/oats-aweb-expert/lessons/real-aw-pins-age-with-the-installed-client.md) - The package pins the real binary's refusals (exit code and message), and those pins break when the installed aw changes behaviour, as `team join` with a bad token did from aw 1.36.43 (first seen here on 1.36.49); run the suite on the clean base on the same host before attributing a failure to a branch, and re-pin the real-aw tables in a dedicated PR, never inside a feature PR.

## Reference

* [How oats.aweb attaches a grant home to the resident's custody service (1.16.1)](/nodes/oats-aweb-expert/references/how-a-grant-home-is-attached-to-custody.md) - The spawn hook's attachment contract, introduced in oats.aweb 1.13.1 and current in 1.16.1: the concrete socket from the custody preflight goes to the mint, the grant record is read back from disk, attachment is proven by the custody status command run as the grant home (never by whoami), a failed proof revokes and removes the fresh grant, renewal keeps the old grant until the new one is proven, and readiness inspects the newest grant home.
* [How oats.aweb does teams (1.16.1)](/nodes/oats-aweb-expert/references/how-oats-aweb-does-teams.md) - The package facts introduced in the first workspace-model-only release (1.14.0) and current in 1.16.1: eligible teams arrive through the environment only (the check stdin stays strict), every instance is minted into the workspace's default team, wider teams are joined by an explicit spawn setting or the teams/join/leave verbs and home operations, each joined team is a further local identity beside the primary that sends with an identity-home selector and receives live through the host wake broker where the runtime supports it (else by polling), joined-team state lives in a provider-owned file mirrored through hook meta, a failed leave keeps the credential, an unmapped primary label falls back to the default team with a warning, and readiness warns on each joined team's receive mode and on the host wake daemon.
