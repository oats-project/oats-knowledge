## Decision

* [A subject verb that reads a commit no spawn or `bases` has validated validates it once, so W_INDEX_STALE is not silent on a moved base](/nodes/oats-okf-expert/decisions/a-subject-verb-validates-a-commit-no-spawn-has-validated.md) - The `W_INDEX_STALE` warning comes from the per-commit validation cache; the 6.0.0 build read only what was cached and so was silent exactly after `--fresh` or a fetch that moved the accepted branch, when staleness is most likely; a subject verb now validates such a commit once and caches it, at the price of one whole-base validation per new commit per host (spawn already pays it); kept: an offline context never fetches for the warning, a validation that cannot run gives no warning, caches nothing and is retried next read, and the verb's answer never depends on it; rejected: documenting the gap as a known limit.
* [Consult explores accepted knowledge remotely; instances get no knowledge copy](/nodes/oats-okf-expert/decisions/consult-explores-accepted-knowledge-remotely-no-per-instance-copy.md) - Instances read their soul's OKF bases remotely at the accepted commit through read-only consult commands served from one host-wide cache, with receipts and base confinement; no instance holds a knowledge copy, and consultation works whether harvest is on or off.
* [okf-base.json is classified by its whole content; the 16 MiB metadata bound refuses only metadata declaring the subject layout](/nodes/oats-okf-expert/decisions/okf-base-json-is-classified-by-its-whole-content.md) - Every 6.0 reader (validator, regenerator, `propose`, the subject verbs) reads `okf-base.json` whole and decides the base's layout from it through one shared function; a plain base's metadata has no 16 MiB bound, as in 5.8 (consult's 64 MiB per-blob read bound still applies); rejected: refusing any metadata above the bound before reading it (broke the "a plain base is served as 5.8 served it" guarantee) and "above the bound means plain" (consistent and bounded, but silently drops a bridged base's layout instead of failing loudly).
* [Personal-data exclusion is one shared instruction, not a publication guarantee](/nodes/oats-okf-expert/decisions/personal-data-exclusion-is-not-a-publication-guarantee.md) - The personal-data exclusion uses one shared wording to preserve lessons without identifying outsiders, while a pre-push hold was rejected as a guarantee unless publication authority is separated.
* [The package's retired 4.x source admission ignores non-soul removed harvest keys and decides the soul opt-out first](/nodes/oats-okf-expert/decisions/retired-4x-host-harvest-keys-carry-no-authority.md) - For a source resolved through its retirement recovery, the knowledge package ignores the removed 4.x keys `harvest`, `harvest-runtime` and `harvest-model` when the host, spawn or workspace recorded them, decides the opt-out first from the recorded soul.yaml text, keeps refusing live 4.x records and refuses any soul `harvest:` value other than `off`; the decision and its rationale are canonical in the oats-maintainer node.

### decision

* [Readers tolerate a stale generated index and a missing id on a bridged base; writers' gates refuse them](/nodes/oats-okf-expert/decisions/readers-tolerate-a-stale-index-and-a-missing-id-writers-refuse-them.md) - On a base with the subject layout, readers (the spawn hook, the subject verbs and, from 6.0.2, `oats okf bases`) read the committed generated indexes as they are and warn, `W_INDEX_STALE` for stale views (6.0.0) and `W_ID_MISSING` for a `claims/` concept merged without its id (6.0.2), while strict validation, `okf-reindex --check`, migration and publication still refuse them; because a refusing reader takes every version-2 soul off the air at spawn for one maintainer-upkeep slip; consequence: the 6.0 view format is final, and a renderer change costs every bridged base a regeneration PR.

## Insight

### constraint

* [oats spawn --preview runs no spawn hook, so the harvester's source check only runs at apply](/nodes/oats-okf-expert/limitations/spawn-preview-runs-no-spawn-hook.md) - The kernel (0.69.x) runs no provider spawn hook in a spawn preview, so the harvester's source check runs only at apply, where a refusal rolls the spawn back and may leave the chosen name occupied as a messaging alias; the provider cannot make preview refuse, documents the fact, and keeps its read-only source check separate from the writing snapshot so a kernel spawn-preview phase would be cheap to adopt.

### lesson

* [A fetch inside the publication gate passes an empty --refmap= and reads the tip from FETCH_HEAD](/nodes/oats-okf-expert/lessons/a-fetch-inside-the-publication-gate-passes-an-empty-refmap.md) - A source-only fetch still applies the clone's configured refspec destinations and can overwrite a local branch before any compare-and-swap; every helper fetch passes an empty `--refmap=` and the gate reads the tip from `FETCH_HEAD^{commit}`.
* [A generated Markdown link must read back its own file through consult's path rules](/nodes/oats-okf-expert/lessons/a-generated-link-must-read-back-through-consults-path-rules.md) - `resolveBasePath` cuts a path at `?` and `#` and decodes `%`, so a generated index never links a path holding one of them (`E_PATH` at generation); otherwise an index entry silently resolves to a different claim than the one it names.
* [A local Git base under the calling instance's home is refused as disposable source custody](/nodes/oats-okf-expert/lessons/a-local-git-base-under-the-instance-home-is-refused-as-disposable-custody.md) - Run from inside an instance (ambient `OATS_INSTANCE_HOME`), the 5.8 CLI (and 6.0.2, whose check is unchanged) refuses a local-path `kind: git` base lying under that home with `E_PATH: Git locator is disposable source custody`; a local-binding rehearsal runs the CLI with a cleared environment and keeps the bound repository, including `TMPDIR`, outside the home. The refusal is correct protection; the trap is in the rehearsal setup.
* [A local publish command binds what it publishes to immutable objects](/nodes/oats-okf-expert/lessons/a-local-publish-command-binds-what-it-publishes-to-immutable-objects.md) - Six rules keep `oats okf propose --apply` publishing only what `--check` showed, although other processes of the same user can change the proposal directory and clone between the two steps: bind by immutable ids, keep Git state inside the clone, pass no file-read value to Git as an option, validate stored blobs not a checkout, carry no tool output in errors, and share one grammar between the provenance writer and parser.
* [Code that writes into a base checkout refuses links and non-regular files before its first read](/nodes/oats-okf-expert/lessons/code-that-writes-into-a-base-checkout-refuses-links-before-its-first-read.md) - Any oats.okf path that writes into a base checkout (the regenerator, `propose --check`'s preparation) walks the whole tree first and refuses symlinks, non-regular files, multiply-linked files and names holding a backslash, then writes through a fresh temp file renamed in place; the consumer's strict validation runs too late to protect a write, because the maintainer regenerates a PR checkout before validating it; `okf-base.json` is read only as a regular single-link file, never through a link or a FIFO.
* [GitHub branch-protection reads answer in three ways, and only two successful reads mean no protection](/nodes/oats-okf-expert/lessons/github-branch-protection-reads-answer-in-three-ways.md) - The rulesets read never shows classic protection and the classic read tells "unprotected" from "unreadable" only by its 404 body, so a branch can be concluded unprotected only when both reads succeed and neither gates; a failed read means unknown, never none.
* [On Node, a Map or Set keyed by long untrusted text is quadratic; key through a bounded key](/nodes/oats-okf-expert/lessons/long-untrusted-keys-make-a-map-quadratic-on-node.md) - A Map, Set or object keyed by text from a base or a committed index (types, kinds, ids, legacy-node names, about and supersedes items) is quadratic when many keys exceed 16383 characters, because V8 hashes such strings by length alone (measured: 3,000 distinct 20,000-character keys, 10.4 s); key untrusted text through a bounded key (the text up to 16,000 characters, else a tagged sha256) and filter references against short trusted keys before building a set.
* [Anything that newly parses a value every base carries must be linear in the input](/nodes/oats-okf-expert/lessons/new-parsing-on-every-base-must-be-linear.md) - A new parse of a value 5.8 treated as an opaque scalar runs on every base, plain ones included, inside a fixed 30 s validation deadline, so it must be linear: 5.8's own comment strip (`/\s+#.*$/`) is quadratic on a long whitespace run with no `#` (10k spaces 310 ms, 30k 1052 ms, 100k over 3 s), a sticky regex with overlapping branches worse; write cursor scanners and test them for exact equivalence against the old regex.
* [propose prepares, judges and publishes one tree of stored blobs, never a checkout](/nodes/oats-okf-expert/lessons/propose-judges-and-publishes-stored-blobs-not-a-checkout.md) - `propose --check` prepares (about:, regenerated indexes), judges (write surface, verdict lanes, validation) and publishes one tree of stored blobs; the accepted side is read from accepted blobs (full listing, whole reads, unreadable is an error, never "absent"); the clone's checkout is only the proposer's view — prepared files go back through Git's checkout and `--apply` stages the checked tree itself — because Git `ident`, `working-tree-encoding` and clean filters otherwise turn a valid proposal into E_SCOPE, E_GIT or E_DIGEST, the last consuming the only publication attempt.
* [Respawn under 5.0 before harvesting" never carried a 4.x seat's notes](/nodes/oats-okf-expert/lessons/respawn-never-carried-a-4x-seats-notes.md) - Respawn is retire-then-spawn, a record is never rewritten and the old notes survive only in the retirement recovery copy whose record carries the same removed 4.x keys, so respawn gives the soul a fresh 5.x seat with empty notes; the retired-source admission is the route to an old seat's notes, and hand-copying into a live 5.x seat that re-proposes under its own name is the only fallback.
* [A text check of a soul.yaml declaration must match a key position, not a word boundary](/nodes/oats-okf-expert/lessons/soul-yaml-text-check-anchors-to-a-key-position.md) - The harvester reads the source soul's soul.yaml as text on purpose, so every check of a declaration there is a regex over the whole file; anchor it to a key position (a line start, or after `{` or `,` in a flow mapping), never to `\b`, which sits between `-` and a letter and makes a bare-word setting match a capability id such as `oats.okf-harvest:`; and sweep the repository's real soul files when reviewing or testing a new text check, because a fixture without such a capability cannot catch it.
* [The frontmatter scalar reader strips one leading and one trailing quote independently](/nodes/oats-okf-expert/lessons/the-frontmatter-reader-strips-one-leading-and-one-trailing-quote.md) - The 5.8 frontmatter parser, and the 6.0 regenerator and validator that keep its scalar rule, strip `^("')` and `("')$` separately, so a title or description that begins or ends with a quoted phrase loses one quote in every reader and generated view (`title: "A" b` reads `A" b`); a tool generating from frontmatter must parse values exactly as the reader does, and an affected concept is fixed by a content edit, never by a generator-side repair.
* [The OATS knowledge base's own CI pins the node roster, so a base-metadata change carries a CI change](/nodes/oats-okf-expert/lessons/the-oats-bases-own-ci-pins-the-node-roster.md) - The base repository's adapter (`scripts/validate.mjs`, pinned OKF 2.1.1) asserts the exact node list and distinct owner UUIDs beyond what OKF's `metadata()` checks (it has no distinct-owner rule), so adding nodes — the bridge's reserved `claims`, `subjects`, `verdicts` under the sentinel owner — passes OKF 2.1.1, 5.8 and 6.0 validation yet fails that CI until the adapter changes in the same PR; the adapter is the base's own and its reviewers' call, and the adapter requires Node major version 22.
