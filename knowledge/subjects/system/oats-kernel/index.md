## Insight

### constraint

* [oats spawn --preview runs no spawn hook, so the harvester's source check only runs at apply](/nodes/oats-okf-expert/limitations/spawn-preview-runs-no-spawn-hook.md) - The kernel (0.69.x) runs no provider spawn hook in a spawn preview, so the harvester's source check runs only at apply, where a refusal rolls the spawn back and may leave the chosen name occupied as a messaging alias; the provider cannot make preview refuse, documents the fact, and keeps its read-only source check separate from the writing snapshot so a kernel spawn-preview phase would be cheap to adopt.

### finding

* [Keep attention ranking out of the kernel's claim record](/nodes/oats-kernel-expert/conclusions/attention-ranking-is-not-a-kernel-queue.md) - The source's provisional position places request deadlines with messaging and ranking in a client view, because a person's request queue extends beyond instances on their kernel hosts and a claim is only a local report.
* [Keep coordination scopes and budgets in the provider payload](/nodes/oats-kernel-expert/conclusions/coordination-declarations-use-provider-payload.md) - The source's provisional position routes coordination declarations through capability settings rather than adding kernel fields, because recording a team's scope or budget does not make the kernel its enforcer or token meter.
* [Require a distinct stall case before adding a progress stamp](/nodes/oats-kernel-expert/conclusions/progress-stamps-need-a-distinct-stall-case.md) - The source's provisional position defers a new progress record because missing handoff notifications call for waiter checkpoints, while neither reported activity nor elapsed silence justifies a kernel stalled verdict.
* [An optional waiting-claim reference would convey no authority](/nodes/oats-kernel-expert/conclusions/waiting-claim-references-convey-no-authority.md) - The source proposes an opaque capability-and-id reference as a claim-to-request join key, with no kernel dereference or mandatory permission reference because a claim cannot establish consent.

### lesson

* [An older Desktop does worse against a newer kernel where it words the consequence itself](/claims/lessons/an-older-desktop-does-worse-where-it-words-the-consequence.md) - In the traced kernel minors, the N-1 Desktop did worse than show less or be refused in four cases, all where it writes the consequence sentence of a destructive action (Stop, Remove) or saves a whole definition (schedule edit). API integers and feature names never caught them, because each change kept the JSON shape and changed its meaning.
* [A client's sentence must hold at every producer of a kernel code](/nodes/oats-desktop-expert/lessons/client-wording-must-hold-at-every-code-producer.md) - Audit a client-authored sentence separately from its outcome classification, because a shared kernel code can cover causes the first example does not.
* [Prove coupled Desktop changes on main and on the prospective kernel merge](/nodes/oats-desktop-expert/lessons/coupled-kernel-and-desktop-landings.md) - When a kernel change would make Desktop actively wrong, keep the Desktop delta reviewable on main but prove the combined tree before maintainers land the pair together.
* [Tests of kernel text own the client's reading, not the kernel's sentences](/nodes/oats-desktop-expert/lessons/kernel-text-tests-own-the-client-reading.md) - Test the client's handling of live producer text without freezing relations between kernel sentences, and derive forbidden-text checks from the producer rather than copied wording.
